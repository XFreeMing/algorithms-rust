## 💡 理解汇编输出的技巧

### 1. 关注优化结果

在 Release 模式下：

**小函数通常会被内联：**
```bash
# 如果找不到 sum_manual 函数，说明它被内联到 main 中了
cargo asm --example asm_demo "asm_demo::sum_manual"
# 输出: Can't find any items matching "asm_demo::sum_manual"
```

这是**好事**！说明编译器优化得很好。

### 2. 使用 `#[inline(never)]` 阻止内联

如果你想单独查看某个函数的汇编，修改代码：

```rust
#[inline(never)]  // 阻止内联
pub fn sum_manual(nums: &[i32]) -> i32 {
    let mut sum = 0;
    for i in 0..nums.len() {
        sum += nums[i];
    }
    sum
}
```

重新编译后就能看到单独的函数了。

### 3. 对比优化级别

```bash
# Debug 模式（未优化）
cargo asm --example asm_demo --debug "asm_demo::main"

# Release 模式（完全优化）
cargo asm --example asm_demo --rust "asm_demo::main"
```

    }

## 📊 汇编代码示例解读

### 典型的循环汇编（ARM64）

```assembly
; 循环开始
.LBB0_1:
    ; 检查索引是否小于长度
    cmp     x8, x9
    b.hs    .LBB0_3
    
    ; 加载数组元素 nums[i]
    ldr     w10, [x0, x8, lsl #2]
    
    ; sum += nums[i]
    add     w11, w11, w10
    
    ; i++
    add     x8, x8, #1
    
    ; 跳回循环开始
    b       .LBB0_1

.LBB0_3:
    ; 循环结束，返回 sum
    mov     w0, w11
    ret
```

### SIMD 优化的循环（高级）

如果数据量大，编译器可能使用 SIMD 指令：

```assembly
; 一次处理 4 个整数
ld1     {v0.4s}, [x0], #16    ; 加载 4 个 i32
add     v1.4s, v1.4s, v0.4s   ; 并行相加
```

## ❓ 常见问题

### Q1: 为什么找不到我的函数？

**A:** 函数可能被内联到调用它的地方了。这是编译器优化的结果。

**解决方法：**
- 添加 `#[inline(never)]`
- 或在 main 函数的汇编中查找内联后的代码

### Q2: 汇编代码太复杂看不懂？

**A:** 正常现象！你不需要理解每一行汇编。

**关注点：**
- 代码的**长度**（优化后更短）
- **指令的类型**（是否有 SIMD 指令）
- **分支的数量**（循环展开后会减少）

### Q3: 手写和迭代器的汇编不完全一样？

**A:** 可能有微小差异，但**性能是相同的**。

**重点是：**
- 时间复杂度相同
- 都被优化到接近最优
- 实际性能测试结果相近
