### 第一阶段：数组理论（9:00-10:00）

#### 1.1 为什么数组从 0 开始编号？

**核心原因：偏移量计算**

数组的访问公式：

```
元素地址 = 首地址 + 索引 × 元素大小
```

**如果从 0 开始：**

- `array[0]` = 首地址 + 0 × 元素大小 = 首地址
- `array[3]` = 首地址 + 3 × 元素大小

**如果从 1 开始：**

- `array[1]` = 首地址 + (1-1) × 元素大小
- 需要多一次减法运算，降低效率

**历史原因：** C 语言设计时选择了从 0 开始，后续语言继承了这一传统。

#### 1.2 数组的核心特性

| 特性     | 时间复杂度 | 说明             |
| -------- | ---------- | ---------------- |
| 随机访问 | O(1)       | 通过索引直接访问 |
| 查找     | O(n)       | 需要遍历（无序） |
| 插入     | O(n)       | 需要移动后续元素 |
| 删除     | O(n)       | 需要移动后续元素 |

**优点：**

- ✅ 支持快速随机访问
- ✅ 内存连续，CPU 缓存友好

**缺点：**

- ❌ 固定大小（静态数组）
- ❌ 插入/删除开销大

### 第三阶段：链表理论（14:00-15:00）

#### 2.1 链表的本质

**定义：** 通过指针将零散的内存块串联起来

```rust
// Rust 链表节点定义
#[derive(Debug)]
struct ListNode {
    val: i32,
    next: Option<Box<ListNode>>,
}
```

**为什么用 `Box` 和 `Option`？**

- `Box<T>`：在堆上分配，避免递归类型大小未知
- `Option<T>`：表示可能为空的指针

#### 2.2 链表类型对比

**单向链表：**

```rust
struct Node {
    val: i32,
    next: Option<Box<Node>>,
}
```

**双向链表：**

```rust
use std::rc::Rc;
use std::cell::RefCell;

struct Node {
    val: i32,
    next: Option<Rc<RefCell<Node>>>,
    prev: Option<Rc<RefCell<Node>>>,
}
```

**循环链表：** 尾节点的 `next` 指向头节点

#### 2.3 链表 vs 数组

| 维度      | 数组 | 链表   |
| --------- | ---- | ------ |
| 内存      | 连续 | 分散   |
| 随机访问  | O(1) | O(n)   |
| 插入/删除 | O(n) | O(1)\* |
| 空间      | 固定 | 动态   |
| 缓存友好  | ✓    | ✗      |

\*注：链表的 O(1) 指已知节点位置的情况

#### 2.4 如何写出正确的链表代码？

**技巧 1：画图** - 每一步都画出指针变化

**技巧 2：哨兵节点（Dummy Node）**

```rust
let mut dummy = Box::new(ListNode { val: 0, next: head });
// 简化边界条件处理
```

**技巧 3：注意边界条件**

- 空链表
- 只有一个节点
- 头尾节点操作

## 🕖 晚上（19:00-21:00）：跳表原理与实现

### 第六阶段：跳表理论（19:00-20:00）

#### 3.1 跳表的诞生背景

**问题：** 链表查找慢 O(n)，能否优化到 O(log n)？

**灵感：** 二分查找需要索引，那就给链表加索引！

#### 3.2 跳表结构

**层级索引：**

```
Level 3:  1 ----------------> 7
Level 2:  1 ------> 4 ------> 7 ---------> 10
Level 1:  1 -> 2 -> 4 -> 5 -> 7 -> 8 -> 9 -> 10
Level 0:  [完整链表]
```

**规则：**

- 最底层包含所有元素
- 上层是下层的抽象（通常每两个取一个）
- 层数通过随机化决定（概率 1/2）

#### 3.3 跳表的操作

**查找流程：**

1. 从最高层开始
2. 向右查找，直到下一个节点 ≥ 目标值
3. 下降一层，重复步骤 2
4. 直到找到或到达底层

**时间复杂度：**

- 查找：O(log n)
- 插入：O(log n)
- 删除：O(log n)

**空间复杂度：** O(n)

#### 3.4 为什么 Redis 用跳表而不是红黑树？

**Redis 作者的回答：**

1. **实现简单** - 跳表代码量远少于红黑树
2. **性能相当** - 平均 O(log n)，常数项小
3. **范围查询友好** - 底层是有序链表，天然支持范围操作
4. **并发友好** - 跳表的局部修改，加锁粒度小
